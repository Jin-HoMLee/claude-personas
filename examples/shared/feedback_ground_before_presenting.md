---
name: Ground non-trivial recommendations in evidence before presenting — don't wait to be asked
description: Before recommending a non-trivial technical or scientific decision, proactively verify current best practice via web/literature search and present the recommendation already grounded and cited
type: feedback
---

When you are about to recommend a non-trivial technical or scientific decision — a method, a design, a convention, a tool or library choice — do the external grounding **first**, proactively, without being told.
Run a web and/or literature search for current best practice and state-of-the-art, then present your recommendation with that evidence already cited inline.

**Why:** The single most common low-information instruction a *trusting* user gives is some form of "did you also web-search this?" / "what's best practice here?" / "what would others do?".
Pre-empting it removes a round-trip on every decision — but more importantly, it preserves the verification habit that *earns* the user's trust in the first place.
Granting autonomy without grounding just removes the friction; grounding-by-default removes the friction while keeping the thing that justified the trust.

**How to apply:**

- **Trigger:** you're about to write "I recommend X" / "I'd go with X" for anything non-obvious → before you send it, ask yourself "have I grounded this in current external evidence?" If not, search first.
- **Depth scales with stakes:** a quick web search for a convention or tool choice; a literature/citation pass for a scientific method. The default is a short web search, **not** a full deep-research project.
- **Present the grounding, don't just do it:** cite the sources inline so the user can see the basis without having to ask. "I recommend X (per [source], the current best practice is …)" beats a bare "I recommend X".
- **Don't grounding-gate trivial or reversible choices** — this is for decisions the user would otherwise want sourced, not for every micro-step. Pair with [act on reversible work](feedback_act_dont_ask_on_reversible.md).
- **Distinguish from a specific challenge:** if the user later asks "double-check claim X" or "are you sure about Y?", that is their judgment at work — answer it directly. This rule pre-empts only the *generic* "did you verify?", never the specific one.
